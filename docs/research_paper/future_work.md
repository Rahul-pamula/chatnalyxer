# VI. Future Work

While the current architectural iteration of Chatnalyxer successfully demonstrates the viability of utilizing multi-modal Large Language Models for automated, passive task extraction from unstructured instant messaging, the system serves as a foundational platform for significant future expansion. The research and development trajectory for Chatnalyxer is broadly categorized into three distinct domains: Platform Ubiquity, Edge-Computed Artificial Intelligence, and Contextual Intelligence Enhancements. The following subsections detail the specific methodologies and technological integrations planned for subsequent iterations of the system.

## A. Platform Ubiquity and Protocol Expansion

The current reliance on WhatsApp limits the system's utility for demographics that favor alternative communication platforms. Future iterations will prioritize architectural decoupling, abstracting the ingestion layer to support multi-protocol monitoring.

**Telegram Integration:** Telegram represents a critical next step due to its massive adoption among university and professional demographics. Unlike WhatsApp's restrictive commercial APIs, Telegram offers a robust, open MTProto API (e.g., utilizing libraries like `Telethon` or `Pyrogram`). Integrating Telegram would dramatically simplify the ingestion architecture. Instead of simulating a companion device via a complex WebSockets implementation, the system could leverage native API keys, offering superior stability, lower memory overhead, and native support for extracting extremely large media files (up to 2GB) without intermediate CDN decryption layers.

**Discord Integration:** Originally designed for gamers, Discord has evolved into the de facto platform for academic study groups and technical open-source communities. Integrating Discord introduces a paradigm shift from simple group chats to structured, channel-based servers (Guilds). Future work involves developing an authorized OAuth2 Discord Bot architecture. This integration will require advanced filtering algorithms, as the system must distinguish between casual voice channels and dedicated `#announcements` or `#project-coordination` text channels. Discord's native webhook support would allow Chatnalyxer to passively listen to designated channels with zero polling latency, directly piping payloads into the FastAPI backend.

**Cross-platform Support:** Currently, the client presentation layer is restricted to mobile operating systems (iOS and Android). However, knowledge workers frequently operate in desktop environments. Future development will leverage the existing React Native codebase to deploy cross-platform desktop applications utilizing React Native for Web or Electron frameworks. This expansion ensures that proactive notifications are delivered seamlessly regardless of the user's current computing environment, providing a unified dashboard accessible from mobile, web, and desktop interfaces.

**Calendar Synchronization:** The internal PostgreSQL database and native Expo Push Notification system provide robust organizational capabilities, but they create a siloed ecosystem. Future work must focus on interoperability. We plan to implement bi-directional synchronization with enterprise calendar systems, specifically Google Calendar and Microsoft Outlook, via OAuth 2.0 integrations. This synchronization will allow tasks extracted by Chatnalyxer to natively populate the user's primary calendar UI. Crucially, the bi-directional nature of this integration ensures that if a user deletes or modifies an event in Google Calendar, the changes are instantly reflected within the Chatnalyxer database, maintaining absolute temporal parity across platforms.

## B. The Transition to Edge-Computed AI

The most significant architectural vulnerability of the current Chatnalyxer system is its absolute reliance on third-party cloud APIs (Google Gemini, Azure AI). This dependency introduces variable latency, recurrent financial costs, and mandates that unencrypted (albeit ephemeral) user data leave the localized environment. The paramount objective for future research is the total localization of the AI processing pipeline.

**Offline AI and Edge AI:** We propose a fundamental architectural pivot toward Edge AI—pushing the computational burden away from centralized cloud servers directly to the edge of the network. By executing the semantic extraction pipeline on the local machine (or within a localized, on-premise network node), the system can achieve true Offline AI capabilities. This ensures that even if a student is disconnected from the internet (e.g., during a flight or in a lecture hall with poor connectivity), locally cached WhatsApp messages can still be parsed, and deadlines can be scheduled without relying on external cloud compute instances.

**On-device Models:** The rapid advancement of Small Language Models (SLMs) makes on-device processing viable for mobile applications. Future iterations of Chatnalyxer will explore the integration of highly quantized (4-bit or 8-bit) LLMs, such as LLaMA-3 (8B) or Google Gemma (2B), running natively on the mobile client utilizing hardware-accelerated frameworks like Apple CoreML or Android NNAPI. While SLMs possess fewer parameters than their cloud-based counterparts, they are exceptionally capable of narrow, zero-shot Information Extraction tasks when heavily fine-tuned. Transitioning to on-device models provides the ultimate privacy guarantee: no conversational data ever leaves the user's physical device. The extraction, parsing, and scheduling occur entirely within the silicon of the smartphone, fundamentally altering the security posture of the application.

**Federated Learning:** If on-device models replace the centralized cloud LLM, the system faces a challenge regarding continuous model improvement. Without centralized data logging, the development team cannot identify failure cases or fine-tune the model against new conversational slang. To resolve this, future research will investigate Federated Learning architectures. In a federated model, the global SLM is periodically downloaded to the user's device. The device trains the model locally based on the user's manual corrections (e.g., if the user manually fixes an incorrectly extracted date). Instead of uploading the user's chat history to the central server, the device uploads only the *cryptographic weight updates* (gradients). The central server aggregates these decentralized, anonymized gradients to improve the global model without ever exposing the underlying private conversational data.

## C. Contextual Intelligence and System Enhancements

The current analytical capabilities of Chatnalyxer are constrained by stateless evaluation and rigid algorithmic logic. Future iterations will focus on imbuing the system with deep contextual memory and predictive intelligence.

**Context Memory:** As identified in the Experimental Evaluation, the current architecture suffers from severe performance degradation when task descriptions are fragmented across multiple, sequential messages (e.g., User A: "When is it due?", User B: "Friday."). The system evaluates each message in isolation. Future work will implement a Context Memory Module. This module will utilize a lightweight vector database (e.g., Pinecone or a local FAISS implementation) or a sliding-window conversational buffer. When a message contains an ambiguous temporal reference or lacks a subject, the LLM will be granted access to the preceding $N$ messages within that specific group chat. By providing the LLM with the immediate conversational history, the system will gain the semantic capacity to resolve highly fragmented, multi-party temporal directives, drastically improving Recall metrics in rapid-fire group chats.

**Smart Recommendations:** The current Notification Engine operates deterministically based on a static priority score. Future iterations will evolve this into a predictive, Smart Recommendation engine. By utilizing historical completion data (i.e., tracking the delta between when a task is assigned and when the user marks it as complete), the system can train lightweight, user-specific machine learning models to detect procrastination patterns. If the system detects that a user consistently delays completing tasks originating from a specific group (e.g., "Advanced Calculus"), the Smart Recommendation engine will dynamically escalate the priority level of future tasks from that group, proactively intervening earlier in the timeline. Furthermore, by analyzing the user's synchronized calendar (identifying periods of high saturation), the system could intelligently suggest optimal "focus blocks" for completing newly extracted tasks, transitioning Chatnalyxer from a passive extraction tool into an active, personalized productivity coach.
