# XIV. MATHEMATICAL FORMULATIONS

To establish a rigorous theoretical foundation for the Chatnalyxer extraction engine, the following mathematical formulations define the probabilistic models, deterministic heuristics, and empirical metrics governing the system's behavior. 

---

## A. Probabilistic and Heuristic Extraction Models

### 1. Task Detection Probability
The probability that a given message $M$ contains an actionable task $T$ is modeled as a conditional probability $P(T|M)$. While the Google Gemini LLM processes this stochastically, it can be mathematically approximated as a sigmoid function over a set of weighted linguistic and contextual features $x_i$:

$$P(T|M) = \frac{1}{1 + e^{-(\beta_0 + \sum_{i=1}^{n} \beta_i x_i)}}$$

**Assumptions:** We assume that the presence of a task is a binary logistic outcome (True/False). The features $x_i$ represent the presence of temporal keywords (e.g., "due", "tomorrow") and directive verbs (e.g., "submit", "read"), while $\beta_i$ represents the latent weights assigned by the LLM during inference.

### 2. Overall Extraction Confidence Score
For multi-modal payloads, the total confidence $C_{total}$ of the extracted task is a compound probability, calculated as the product of the preprocessing modality confidence $C_{media}$ (e.g., Azure OCR confidence) and the semantic LLM confidence $C_{LLM}$:

$$C_{total} = C_{media} \times C_{LLM}$$
$$\text{Where } C_{media} \in [0, 1] \text{ and } C_{LLM} \in [0, 1]$$

**Assumptions:** This formulation assumes that the preprocessing and semantic extraction stages are statistically independent events. A failure in OCR (low $C_{media}$) mathematically caps the maximum possible confidence of the final extracted task, acknowledging the cascading nature of pipeline errors.

### 3. Priority Score Calculation
The deterministic Priority Score $S_p$ is a composite scalar derived from two normalized vectors: the Temporal Urgency $\Delta t$ and the Linguistic Weight $L_w$. Let $T_0$ be the message origination time and $T_{due}$ be the extracted deadline.

$$S_p = \left( \alpha \cdot e^{-\lambda(T_{due} - T_0)} \right) + \left( \beta \cdot \sum_{k \in M} W(k) \right)$$

**Assumptions:** The temporal urgency is modeled as an exponential decay function $e^{-\lambda \Delta t}$, assuming that urgency spikes non-linearly as the deadline approaches. $W(k)$ represents a heuristic dictionary lookup assigning static weights to specific priority keywords $k$ found within message $M$. $\alpha$ and $\beta$ are tunable hyperparameters balancing the two vectors.

### 4. Temporal Confidence
Temporal Confidence $C_t$ quantifies the mathematical ambiguity of a relative date expression. Let $V_m$ be the variance in seconds of the possible time window implied by the message.

$$C_t = 1 - \left( \frac{V_m}{V_{max}} \right)$$

**Assumptions:** An absolute expression ("August 5th at 5:00 PM") has $V_m = 0$, yielding $C_t = 1.0$. A highly ambiguous expression ("sometime next week") implies a variance $V_m = 604800$ seconds (7 days). If $V_{max}$ is defined as a one-month window, highly ambiguous terms severely degrade $C_t$. The system relies on the LLM to collapse $V_m$ to a single point, but $C_t$ measures the inherent risk of that collapse.

### 5. Notification Activation Score
The decision to fire a push notification at current time $t_c$ is governed by an activation function $N(t_c)$. Let $\tau$ be the user-defined notification threshold.

$$N(t_c) = \begin{cases} 
1, & \text{if } (T_{due} - t_c) \le \tau \text{ and } S_p \ge P_{threshold} \\
0, & \text{otherwise}
\end{cases}$$

**Assumptions:** This is a deterministic step function. Notifications are strictly binary (sent or not sent) and assume continuous temporal polling by the APScheduler daemon where $t_c$ approaches $T_{due}$.

## B. Experimental Evaluation Metrics

The following metrics are utilized to empirically evaluate the pipeline against the annotated ground-truth corpus (CEC-10K).

### 6. Precision ($P$)
The ratio of correctly extracted and scheduled tasks to all tasks generated by the system.
$$P = \frac{True \ Positives \ (TP)}{True \ Positives \ (TP) + False \ Positives \ (FP)}$$

### 7. Recall ($R$)
The ratio of correctly extracted tasks to the total number of actual tasks present in the ground truth corpus.
$$R = \frac{True \ Positives \ (TP)}{True \ Positives \ (TP) + False \ Negatives \ (FN)}$$

### 8. F1 Score ($F_1$)
The harmonic mean of Precision and Recall, providing a singular accuracy metric resilient to class imbalances in the dataset.
$$F_1 = 2 \cdot \frac{P \cdot R}{P + R}$$

**Experimental Evaluation Methodology:** These three metrics are evaluated using a hold-out test set from the CEC-10K corpus. Human annotators establish the absolute boundaries of $TP, FP,$ and $FN$. A $TP$ is only recorded if the extracted ISO-8601 $T_{due}$ matches the human-annotated ground truth within a stringent margin of error ($\pm 1$ hour).

## C. System Performance and Computational Complexity

### 9. End-to-End Latency
Total system latency $L_{total}$ is the arithmetic sum of the processing durations across the distributed microservices for a given payload $i$.

$$L_{total}(i) = L_{ingest} + L_{queue} + L_{media}(i) + L_{LLM} + L_{DB}$$

**Assumptions:** $L_{ingest}$ and $L_{DB}$ are assumed to be near-constant ($\mathcal{O}(1)$). $L_{media}(i)$ is highly variable, assumed to be $0$ for plain text, but scaling linearly $\mathcal{O}(S)$ with the file size $S$ for audio and PDF processing. $L_{LLM}$ is heavily dependent on the external API network conditions and token generation length.

### 10. Time Complexity
Assuming $N$ represents the number of incoming messages and $M$ represents the number of active tasks residing in the database.

*   **Ingestion:** $\mathcal{O}(1)$ per message utilizing Hash Sets.
*   **Scheduling Daemon:** $\mathcal{O}(\log M + K)$, where the B-Tree index allows logarithmic isolation of $K$ tasks whose $T_{due}$ falls within the polling window.

### 11. Space Complexity
*   **Volatile Memory (RAM):** $\mathcal{O}(Q \cdot \bar{S})$, where $Q$ is the number of payloads currently residing in the FastAPI asynchronous processing queue, and $\bar{S}$ is the average byte size of a decrypted payload. Due to Ephemeral Processing, data is purged post-extraction, ensuring RAM usage scales strictly with instantaneous traffic volume, not historical data retention.
*   **Persistent Storage (Disk):** $\mathcal{O}(U \cdot T_{avg})$, where $U$ is the total number of registered users and $T_{avg}$ is the average number of extracted, structured JSON tasks per user. Because raw media is not persisted, disk growth scales linearly and highly efficiently with metadata volume.

**Experimental Evaluation Methodology:** Computational complexity is empirically validated during load testing (e.g., using Apache JMeter). Latency $L_{total}$ is measured by injecting localized timestamp markers into the payload at the edge boundary and calculating the delta upon database `INSERT`. Space complexity is validated by monitoring container RAM utilization (via cgroups) under simulated viral load to ensure memory growth conforms to the theoretical $\mathcal{O}(Q \cdot \bar{S})$ limit without precipitating Out-Of-Memory (OOM) crashes.
